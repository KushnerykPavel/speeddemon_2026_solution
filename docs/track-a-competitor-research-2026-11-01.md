# Track A: competitor research and a route toward top ten

Research date: 2026-11-01. Scope: Track A machine-score top ten. “Go to top ten” is interpreted as reaching that rank; the current implementation is Rust, not Go. This report does not establish an overall top-ten result. No solution changes, benchmarks, remote benchmark execution, submission or push were performed.

## Recommendation

Use the measured rewrite at `ea2ee343274655e5638cba68fd567034e83d8f1e` as the score anchor, restore exact endpoint identity, and profile that corrected baseline before another architectural rewrite. Prioritize genuine source simplification, cheaper exact-checked endpoint hashing and removal of the output staging copy; scratch changes require resident-allocation evidence first. Reusing one thread pool is conditional on measured startup cost. Streaming and a C++ port are later alternatives, not established requirements for top ten.

The current source already contains the shared endpoint table, four-byte per-hour records with a full-width overflow side list, parallel input-page reclamation, and mapped output. Old plans recommending those mechanisms as future work are stale. Current `main.rs` SHA-256 is `2edbdfe7106b01372b7b95f5394c36a76828c4d9e8f537d3bd680610f4c9b29b`. The refreshed official feed contains a matching result for this revision and supersedes the older local PERF table. ## Rules that change the choice

The current official formula is:

```text
K = (T_ref/T)^0.50 × min(M_ref/M, 50)^0.20
    × min(S_ref/S, 1)^0.15 × (D_ref/D)^0.15
points = clamp(50 log10(K), 0, 100)
```

For comparable candidates away from caps, use `K_after/K_before = T_ratio^-0.50 × M_ratio^-0.20 × S_ratio^-0.15 × D_ratio^-0.15`. A 10% time reduction is approximately +5.4% K; a 10% memory or source reduction gives approximately +2.1% or +1.6% K respectively. These are arithmetic effects, not measured improvements. [Official scoring implementation](https://github.com/hackathon-raptors/speed-demon-2026/blob/main/harness/scoring.py), blob `f3858e2e7b04b73b1229d48b99579648614ffddb`.

T is the mean of the middle three of five exec-to-exit measurements; M is the maximum of five fresh parent-cgroup peaks. M includes charged tmpfs pages. S is counted after the language's default formatter, so compressing statements or changing formatter settings does not establish a source win. Runtime dependency additions also have a scored cost. [Official harness README](https://github.com/hackathon-raptors/speed-demon-2026/blob/main/harness/README.md), blob `e03148758e897e07c4703c4698bf6de4fe90c1b0`.

On the configured scoring host, the work directory is tmpfs and each run binds a fresh output directory. Therefore HighVelocity's disk-backed CI reductions from output writeback/cache advice are not transferable to the official `/out`; nor does overlap of truncating a previous output address a fresh official directory. `O_DIRECT` is not a route to avoiding the tmpfs output charge. Retain the distinction between disk-backed CI, VPS and the official host. [Host setup](https://github.com/hackathon-raptors/speed-demon-2026/blob/main/harness/setup-box.sh), [per-run mounts](https://github.com/hackathon-raptors/speed-demon-2026/blob/main/harness/run_submission.py), [local memory research](track-a-research-2026-11-01.md).

The spec requires exact endpoint-byte identity and exact nearest-rank percentiles for full u32 latencies. It does not promise the disorder bound needed to finalize an hour permanently after observing a later one. A streaming version must detect violations and recover exactly, including arbitrary legal ordering. [Official Track A specification](https://github.com/hackathon-raptors/speed-demon-2026/blob/main/specs/a-ingest.md).

Overall ranking is a separate objective: it uses the best three track totals, requires at least three scored tracks, and final track totals include 65% machine points and 35% judging. Improving only A cannot establish overall top ten. [Official scoring implementation](https://github.com/hackathon-raptors/speed-demon-2026/blob/main/harness/scoring.py).

## Correctness and measurement gate

`Names::slot` currently returns an ID on hash equality, including a failed compare-and-swap returning the same hash, without comparing the endpoint bytes. Different names with equal fingerprints would be merged. Before adopting a cheaper fingerprint, restore exact equality and continue probing on unequal keys. Claiming a hash slot is not the same as publishing its initialized name: the protocol must wait for or acquire a completely initialized immutable name before comparison, and concurrent insertion of the same name must not produce inconsistent IDs. [Current `Names::slot`](../track-a/src/main.rs).

Use forced equal-hash names in direct dictionary tests, including concurrent insertions, plus reference comparisons on multiple seeds, empty input, maximum u32 latencies, overflow-sentinel boundaries, duplicate values, sparse hours and reordered inputs. Keep a source-hashed exact baseline separate from the faster hash-only version. Reuse the existing validator and benchmark workflow; do not invent another benchmark harness. [Existing forced-collision experiment](../tests/performance/2026-11-01-track-a-chunks4/README.md), [baseline validation](../tests/BASELINE_VALIDATION.md).

The archived VPS/Lyceum sampling profiles describe `69aefa2`, not this rewrite. Their SipHash, UTF-8 and full-sort percentages cannot identify current bottlenecks. The later step-11 instruction claims also lack matching raw current-source attribution in the inspected archive. Use the current official T/M/S/D above as the score anchor; record comparable local release T, canonical S/D, fresh cgroup M, and diagnostic phase walls for parse, rank, hour work, output and exit. Distinguish CPU samples from elapsed critical-path time. [VPS profile provenance](../tests/performance/2026-11-01-ingest-perf-flamegraphs/README.md), [Lyceum provenance](../tests/performance/2026-11-01-track-a-rl-lyceum/README.md), [PERF](../track-a/PERF.md).

## Remaining hypotheses, ranked by conditional K per engineering hour

The table is an explicit planning model, not measured evidence or a calibrated forecast. Ratios are independent illustrative after/before assumptions anchored to current official K=35.052698; replace them after the gate above. They must not be added or multiplied as a promised combined gain. Hours include implementation and validation but exclude board queue time. D remains unchanged throughout.

| Priority | Isolated change | Assumed T / M / S ratios | Assumed effort | Conditional ΔK / hour |
|---|---|---|---:|---:|
| 1 | Simplify actual redundant code after canonical S count | 1.00 / 1.00 / 0.90 | 1.5 h | about +0.37 |
| 2 | Sampled hardware CRC fingerprint, retaining exact equality | 0.96 / 1.00 / 1.02 | 3 h | about +0.21 |
| 3 | Format directly into the known output range | 0.98 / 0.98 / 1.02 | 3 h | about +0.13 |
| 4 | One persistent worker pool for all phases | 0.96 / 1.00 / 1.05 | 4 h | about +0.12 |
| 5 | Scratch changes only if allocation evidence supports them | 1.00 / 0.98 / 1.01 | 1.5 h | about +0.06 |

These conservative central scenarios cannot themselves promise the required +40.73% K. Near ties are not meaningful; engineering effort and S can reverse the ordering. Pool reuse moves ahead if measured startup is large. Scratch is low priority until actual resident-page evidence supports it, because initialized allocation may already be lazy.

1. **Source simplification.** Remove duplicated state/work and unnecessary abstraction only when default rustfmt plus official static counting confirms fewer lines. Do not sacrifice exact identity, synchronization or bounds guarantees. Cache Me's successful trims show that unchanged performance with fewer counted lines can improve K; its Rust port also illustrates why a smaller source must be measured rather than inferred from file length. Reject changes whose time/memory cost erases the S gain. [Current source](../track-a/src/main.rs), [Cache Me PERF, steps 4–7 and 24](https://github.com/manusingh090/speed-demon-2026-entry/blob/speed-demon/track-a/PERF.md), [official static axes](https://github.com/hackathon-raptors/speed-demon-2026/blob/main/harness/static_axes.py).

2. **Exact-checked sampled hashing.** Our parser still hashes every endpoint word through a serial rotate/multiply chain. Both competitors use fixed samples and hardware CRC as fingerprints while checking the bytes for identity. Experiment only with the hash after equality is restored; retain safe handling of short names and collisions and avoid per-record CPU dispatch. Measure parse and full-process T, instructions, table-probe behavior and S. Reject if an end-to-end complete-K improvement is unresolved. It adds no dependency, but SSE4.2 target compatibility or a fallback must be explicit. [Our parser](../track-a/src/main.rs), [Cache Me PERF](https://github.com/manusingh090/speed-demon-2026-entry/blob/speed-demon/track-a/PERF.md), [HighVelocity hash qualifications](https://github.com/insightlabs38-pixel/sd-ta/blob/main/track-a/PERF.md), [Rust CRC intrinsic](https://doc.rust-lang.org/core/arch/x86_64/fn._mm_crc32_u64.html).

3. **Direct mapped formatting.** The mapped-output design is only partial: each worker still builds an hour in `Vec<u8>` and copies it into the mapping. A bounded writer into each precomputed disjoint byte range could remove allocation, copying and duplicate output residency. Preserve exact decimal widths, byte count, empty output and disjointness, and retain an end-position assertion. Compare full T, output-phase CPU, peak M and formatted S. Reject a change that merely moves CPU or memory between phases. [Our text phase](../track-a/src/main.rs), [Cache Me PERF, steps 3–4](https://github.com/manusingh090/speed-demon-2026-entry/blob/speed-demon/track-a/PERF.md).

4. **Pool reuse.** `run(workers, ...)` creates and joins a fresh scoped pool for parsing, hours and text: three generations of workers. A single pool with explicit phase barriers may reduce fixed launch/teardown costs. This is genuinely missing from our current source but incurs Rust synchronization/lifetime complexity and likely S growth. Measure startup and barrier wall time first; reject if their upper bound cannot pay the source cost. Any phase failure must wake peers and avoid deadlock. [Our `run` and `summarize`](../track-a/src/main.rs), [Cache Me PERF, step 3](https://github.com/manusingh090/speed-demon-2026-entry/blob/speed-demon/track-a/PERF.md).


5. **Scratch allocation.** The comment says “not zeroed,” but the code requests `vec![0_u32; most]` for every hour worker. First inspect actual allocation/page-fault behavior: zero-initialized allocation can use lazy zero pages, so source syntax alone does not prove every page is touched. Compare a sound write-before-read uninitialized backing allocation or per-worker required capacity; do not create references to uninitialized u32 values. All groups must be completely scattered before selection. Keep largest-hour sizing stable to avoid reallocating while peers fault pages. Reject if repeated cgroup peaks do not fall enough to pay for any time/S cost. [Our hour scratch](../track-a/src/main.rs), [Cache Me PERF, steps 10–11](https://github.com/manusingh090/speed-demon-2026-entry/blob/speed-demon/track-a/PERF.md), [Rust `MaybeUninit` safety](https://doc.rust-lang.org/std/mem/union.MaybeUninit.html).

## Lower-priority alternatives and rejection rules

- **Streaming:** consider only after the small changes and current profile. It can reduce live records but introduces prefix tracking, late-record recovery, queued output and scheduling costs. Our existing four-byte storage reduces the potential saving, and tmpfs output remains resident. Require bounded allocation, full-u32 support, exact arbitrary-order fallback, and a measured complete-K win. HighVelocity's disk CI memory figures cannot serve as the predicted official M. [HighVelocity streaming log](https://github.com/insightlabs38-pixel/sd-ta/blob/main/track-a/PERF.md), [our memory model](track-a-research-2026-11-01.md).
- **SIMD selection/prefetch:** conditional on a new profile, not the old sort/SipHash flamegraphs. Competitors report both wins and regressions, and larger selectors can be K-neutral after S. Retain Rust's existing exact selection until the current whole-workload share establishes headroom. [Both competitor logs](https://github.com/insightlabs38-pixel/sd-ta/blob/main/track-a/PERF.md), [Cache Me selection/prefetch trials](https://github.com/manusingh090/speed-demon-2026-entry/blob/speed-demon/track-a/PERF.md).
- **Worker/chunk tuning:** the previous eight-to-four chunk experiment was inconclusive on an older corrected `db59a56` baseline. Revisit only if this changed architecture shows measured imbalance, with actual scoring-host topology separated from VPS oversubscription. [Experiment](../tests/performance/2026-11-01-track-a-chunks4/README.md).
- **C++ port:** a possible source-size strategy if current canonical Rust S makes the target unattainable under realistic T/M, but no language-only win has been established for our code. Estimate the measured S advantage first, retain the Rust champion, and budget a full correctness qualification. [Cache Me's port comparison](https://github.com/manusingh090/speed-demon-2026-entry/blob/speed-demon/track-a/PERF.md).

## Acceptance protocol

Preserve uncommitted work and the best verified implementation. Record baseline/candidate revision and source hashes, compiler/flags, CPU/affinity/workers, input hashes, warmup, timed boundary and memory method. Test one primary hypothesis; run baseline/candidate serially in alternating AB/BA order with identical conditions. Check every timed output and multiple seeds/edge cases. Use fresh per-run cgroups and the official max-of-five M convention when predicting official K. Count canonical S/D; save raw evidence under `tests/performance/` and update `track-a/PERF.md` with accepted, rejected or inconclusive status. Effects within noise remain inconclusive. After three unsuccessful experiments, refresh independent research rather than continue local tuning. [Project instructions](../AGENTS.md), [existing experiment protocol](../tests/performance/2026-11-01-track-a-chunks4/README.md), [official harness](https://github.com/hackathon-raptors/speed-demon-2026/blob/main/harness/README.md).

The next concrete experiment is an exact current-source qualification and measurement, followed by one small candidate selected from that evidence. Reaching top ten requires a verified complete-K gain against the refreshed official baseline and a new cutoff check; the concrete target is roughly 20 ms with materially less source, or roughly 17.4 ms at current M/S.
